# Refute Check Skill — 반박 검증

사용자가 결론·원인 보고의 검증을 요청하면 아래 절차를 따른다.

## 절차

1. 대상 결론 문서를 읽고, 결론을 **한 문장**으로 요약한다.
2. **입장 전환 — "이 결론은 틀렸다"를 전제**로, 반례를 3가지 경로에서 찾는다.
   각 경로에서 실제 데이터(`data/incident/` 로그)를 grep 등으로 확인한다:

   <!-- [빈칸] 각 경로에서 '무엇을 확인할지'를 채우세요. 예시가 큰 힌트입니다. -->
   - **시간 반박** — (채우기)
     예) 지목된 원인 시점 **이전** 날짜의 로그에도 같은 증상이 있는지 확인
   - **사례 반박** — (채우기)
     예) 지목된 조건에 해당하지 **않는** 서비스(미배포 등)에도 같은 증상이 있는지 확인
   - **대안 반박** — (채우기)
     예) 같은 시기에 시작된 **다른 원인 후보**(만료·설정 변경·용량 등)가 로그에 있는지 확인

3. `output/refute-log.md` 로 결과를 작성한다. **형식 고정**:
   - 첫 줄: `# Refute Log`
   - `CLAIM: <검증 대상 결론 한 문장>`
   - `REFUTE-TIME: <확인한 것과 결과 — 반례 발견 여부>`
   - `REFUTE-CASE: <확인한 것과 결과 — 반례 발견 여부>`
   - `REFUTE-ALT: <확인한 것과 결과 — 대안 원인 발견 여부>`
   - `VERDICT: REJECTED` 또는 `VERDICT: ACCEPTED` — **반례가 1건이라도 나오면 REJECTED**
   - REJECTED 인 경우: `TRUE-CAUSE-CANDIDATE: <대안 원인 후보 한 줄>`
   - ACCEPTED 인 경우: "반박 3회 실패"를 본문에 명시
   - **마지막 줄: `GENERATED-BY: refute-check-skill`**

## 금지

- 결론을 지지하는 증거만 수집하는 것 (이 스킬의 일은 무너뜨려 보는 것)
- 로그에서 확인하지 않은 수치·인용 사용
