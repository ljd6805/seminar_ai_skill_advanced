# 사건 ⑥ — 산출물 약속 (Artifact Contract)

> 슬라이드: PART 2 · 사건 06 — "스킬의 결과를 다음 스킬로 넘길 때, 전달 사고가 납니다"
> PART 2는 하나의 장애 대응 프로세스(수집→분석→초안→검증)를 ⑥⑦⑧⑨로 이어 완성하는 연작이다.

## 시나리오
요약 스킬(log-digest)의 결과를 리포트 스킬(incident-report)이 이어받아야 하는데,
결과가 대화에만 있으면 리포트 스킬이 "요약을 못 찾는다". 사람이 스크롤·복붙하다
구버전을 붙여 사고가 난다. 두 스킬은 각자 정상 — 문제는 둘의 **연결**이다.

## 체험 방법
1. **Before** — `before/` 에서:
   - `logs/incident.log 요약해줘` (log-digest) → 결과가 화면에만 남는다.
   - 이어서 `방금 요약으로 장애 리포트 만들어줘` (incident-report)
   - 관찰: "그 요약이 어디 있죠?" — 경로·형식·버전이 어디에도 없다.
     함수로 치면 A가 return 없이 print만 하고, B가 콘솔을 긁는 꼴.
2. **After** — `after/` 에서 같은 두 요청.
   - 관찰: log-digest 가 `output/digest.md`(3섹션 + `DIGEST-VERSION: 1`)로 저장 →
     incident-report 가 그 파일의 버전을 확인하고 **그것만** 근거로 작성.
   - 실험: digest.md 의 마지막 `DIGEST-VERSION` 줄을 지우고 다시 리포트를 요청하면,
     소비자가 "옛 파일·복사본으로 간주"하고 **거부**하는지 확인해 보라.

## 관찰 포인트
- 전달 통로가 대화 → **약속된 파일과 형식(경로·형식·버전)**으로 바뀌는가.
- 이 약속이 책임지는 범위는 **전달까지** — 내용 품질 검사는 사건 ⑧의 몫.
- 새 스킬을 만든 게 아니라 **기존 두 스킬에 약속을 한 절씩** 나눠 적은 개조다.

**한 줄 정리 — 약속이 있어야 부품.** 약속을 지키는 스킬은 어떤 조합으로도 이어 붙는다.
