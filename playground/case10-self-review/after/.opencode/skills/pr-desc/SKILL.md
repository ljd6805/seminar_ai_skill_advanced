# PR Description

## 절차
1. 초안을 `output/draft.md` 에 작성한다.
2. **역할 전환 — "지금부터 리뷰어다."**
   `references/review-checklist.md` 를 로드하고, 항목별로 **결함만** 찾는다.
   (칭찬 금지 · 지적은 항목 번호와 함께)
3. 지적을 반영해 고친다. 2~3을 **최대 2회** 반복.
4. 마지막 리뷰에서 지적 0건이면 제출한다.
   0건이 안 되면: 남은 지적을 정리해 사용자 판단에 넘긴다.

## 검토의 한계
역할 전환은 검토 관점을 바꾸지만 독립 검증을 만들지는 않는다. 지적 0건은 체크리스트 범위에서 미발견이라는 뜻이다. 사실·수치·실행 결과는 원본이나 도구로 확인하고, 남은 불확실성을 제출 시 표시한다.

- **잘 잡히는 것**: 체크리스트로 판정할 수 있는 누락·형식·표현(#2 테스트 영향, #5 롤백, #7 과장). 효과의 대부분은 역할 선언이 아니라 체크리스트와 "결함만·항목 번호" 형식 강제에서 나온다. 체크리스트 없는 역할 전환은 다시 인상 평가로 돌아간다.
- **잘 안 잡히는 것**: 추론 오류, 사실 오류, diff를 잘못 읽은 초안. 같은 모델은 같은 맹점을 공유한다. 이런 항목은 반박 검증(⑪)이나 스크립트 채점(⑫)으로 넘긴다.

## 리뷰어를 새 세션·서브에이전트로 분리할 때
1. 리뷰어에게는 `output/draft.md`, `work/changes.diff`, `references/review-checklist.md` **만** 넘긴다. 작성 대화는 넘기지 않는다.
   - 얻는 것: 작성 추론에 끌리는 앵커링이 끊긴다. 리뷰 왕복 토큰이 메인 컨텍스트에 쌓이지 않는다. 리뷰어를 다른 모델로 바꿀 수 있다.
   - 남는 것: 같은 모델이면 자기 문체를 알아보고 후하게 보는 편향이 남는다. 의도를 모르는 리뷰어는 일부러 뺀 항목도 결함으로 찍어 거짓 양성이 는다.
2. 리뷰어의 출력은 항목 번호와 근거만 받는다. 거짓 양성은 작성자가 근거를 적어 기각하고, 기각 사유를 제출물에 남긴다.
3. 반복 상한(2회)과 "남은 지적은 사용자 판단으로" 규칙은 그대로 둔다. 분리된 리뷰어는 결함을 더 많이 찾으므로 상한이 더 중요해진다.
4. 가능하면 리뷰어를 다른 모델로 둔다. 링크·섹션 존재처럼 기계로 판정되는 항목은 스크립트로 빼고, LLM 리뷰어에는 #7 같은 판단 항목만 남긴다.
