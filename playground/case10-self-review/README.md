# 사건 ⑩ — 자가 리뷰 루프 (Self-Review Loop)

> 슬라이드: PART 3 · 사건 10 — "방금 쓴 에이전트에게 물으면, 항상 '괜찮다'고 합니다"

## 시나리오
PR 설명을 쓴 뒤 "괜찮아?"라고 물으면, 같은 컨텍스트·같은 프레임이라 자기 글을
정당화한다. 매번 사람 리뷰에서 같은 3건(테스트 영향 누락·롤백 없음·과장 표현)이 잡힌다.

## 체험 방법
공통 입력: `work/changes.diff`
1. **Before** — `before/` pr-desc: 초안 → "보여준다"로 끝. 검토 단계가 없다.
   - 초안 후 `괜찮아? 빠진 거 없어?` → 대체로 "잘 정리되어 있습니다".
2. **After** — `after/` pr-desc: 작성 후 **리뷰어로 역할 전환** + 체크리스트.
   - `work/changes.diff 로 PR 설명 써줘`
   - 관찰: 초안(`output/draft.md`) → "지금부터 리뷰어다" 로 `references/review-checklist.md`
     항목별 결함 지적(#2 테스트 영향, #5 롤백, #7 과장) → 반영 → 재리뷰(최대 2회) → 0건이면 제출.
   - 참고: `work/draft.weak.md` 는 일부러 과장·모호 표현을 넣은 초안이다.
     `이 초안을 체크리스트로 리뷰해줘` 로 넣으면 #7의 근거 없는 과장·모호함 등을 검토한다.

## 관찰 포인트
- 같은 모델이라도 **프레임(역할 선언)과 체크리스트**를 바꾸면 남의 눈이 되는가.
- 기준이 팀 공유 파일이라 **누가 써도 같은 수준**으로 잡히는가.
- 사람 리뷰에는 "남은 것만" 올라간다.

**한 줄 정리 — 같은 모델, 다른 프레임.** 사람의 페어 리뷰를 스킬로 옮긴 것.

3. **확장 — 리뷰어 분리** (선택): 새 세션 또는 서브에이전트를 열고 `output/draft.md`·`work/changes.diff`·
   `references/review-checklist.md` 세 파일만 넘겨 `체크리스트 항목별로 결함만, 항목 번호와 근거로 답해줘` 라고 요청한다.
   - 관찰: 같은 세션 리뷰(2번)와 지적 건수·내용을 비교한다. 분리된 리뷰어는 작성 이유를 모르므로
     지적이 늘고, 그중 일부는 의도적으로 뺀 항목(거짓 양성)이다.

## v0.9 검토 기준

역할 전환과 새 세션은 독립 검증을 보장하지 않는다. 지적 0건은 해당 체크리스트에서 미발견이라는 뜻이다. 불확실성 표현을 지우기보다 근거와 확인 계획을 남긴다.

## 한계와 강화 단계

**효과는 조건부다.** 이 루프가 잡는 것은 체크리스트로 판정할 수 있는 누락·형식·표현이다. "좋은가?"라는
열린 평가를 "#2가 있는가?"라는 판정으로 바꾸기 때문에 탐지가 된다. 추론 오류·사실 오류·diff를 잘못 읽은
초안은 같은 모델이 같은 맹점을 공유해 놓치기 쉽다. 그런 항목은 사건 ⑪(반박 검증)과 ⑫(스크립트 채점)이 맡는다.
체크리스트 없는 역할 선언만으로는 다시 인상 평가로 돌아간다.

| 단계 | 방법 | 얻는 것 | 남는 것 |
|---|---|---|---|
| ① | 같은 세션 역할 전환 + 체크리스트 (이 키트) | 가장 싸다. 판정 가능한 누락을 잡는다 | 작성 추론을 그대로 보므로 자기 정당화에 끌린다 |
| ② | 초안·diff·체크리스트만 넘긴 새 세션·서브에이전트 | 앵커링 제거. 메인 컨텍스트에 리뷰 토큰이 안 쌓인다 | 같은 모델의 자기 선호 편향. 의도를 몰라 거짓 양성 증가 → 상한 2회와 사용자 이관이 더 중요 |
| ③ | 리뷰어를 다른 모델로 | 공유 맹점 축소 | 비용·환경 제약. 여전히 독립 검증은 아니다 |
| ④ | 기계 판정 항목(링크·섹션 존재)은 스크립트로 | 결정적 항목은 확정 판정 | LLM 리뷰어에는 #7 같은 판단 항목만 남는다 (사건 ⑫) |

서브에이전트 사용 여부는 사내 opencode 버전·설정에 따라 다르다. 파일 세 개를 넘기는 새 세션 방식은 어디서나 동작한다.
