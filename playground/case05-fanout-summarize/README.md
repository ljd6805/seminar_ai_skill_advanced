# 사건 ⑤ — 분업 요약 (Fan-out & Summarize)

> 슬라이드: PART 1 · 사건 05 — "아무리 아껴도, 한 번에 안 들어가는 일이 있습니다"

## 시나리오
릴리즈 전 모듈 6개(체험용, 실제는 12개)를 전부 보안 점검. ①~④로 아껴도
코드+결과가 한 창에 계속 쌓이면 총량 상한(1×202k/262k)을 넘는다. 각 모듈에는
서로 다른 취약점이 하나씩 심겨 있다(`modules/m01_auth` … `m06_config`).

| 모듈 | 심어 둔 취약점(정답) |
|---|---|
| m01_auth | MD5 해시 + 정적 솔트 |
| m02_query | SQL 인젝션(문자열 포매팅) |
| m03_files | 경로 검증 없음(path traversal) |
| m04_exec | shell=True 커맨드 인젝션 |
| m05_token | 예측 가능 난수 토큰 |
| m06_config | 하드코딩된 자격증명 |

## 체험 방법
1. **Before** — `before/` 스킬로: `modules/ 전부 보안 점검해줘`
   - 관찰: 한 세션이 6개 코드를 다 떠안는다. 모듈 수를 늘릴수록(복제) 뒤쪽
     모듈에서 앞 결과가 요약으로 뭉개지는 지점이 온다.
2. **After** — `after/` 조율자 스킬로 같은 요청.
   - 관찰: `output/audit/plan.md` 로 조각을 나누고, 모듈마다 **서브에이전트/새 세션**에
     위임(각자 깨끗한 창) → 약 10줄 요약과 상세 근거를 `output/audit/mNN.md` 로 회수 →
     부모는 보고를 종합하고 중요한 판단·모듈 간 위험은 코드에서 재확인한다.

> 서브에이전트 기능이 없는 opencode 버전이면, 위임 지시문을 그대로 **새 세션**에
> 붙여 각 모듈을 점검하고 결과 파일만 부모 세션이 모아도 동일한 원리다.

## 관찰 포인트
- 작업자별 독립 창으로 분담되는가. 부모의 창이 N×202k/262k로 확장되지는 않는다.
- 요약과 근거가 연결되고, 필요한 원문을 부모가 재확인할 수 있는가.
- 요약에서 중요한 근거나 경계 간 위험이 빠졌다면 추가 확인한다.

**한 줄 정리 — 분담하고 근거를 연결한다.** 상태 파일과 재개를 함께 설계한다.

## v0.9 검토 기준

작업자별 컨텍스트는 독립적이며 N×202k/262k의 공유 창이 아니다. 약 10줄 요약과 상세 근거를 회수하고 중요한 판단·모듈 간 위험은 부모가 원문으로 재확인한다.
