# 사건 ② — 스크립트 위임 (Script Offloading)

> 슬라이드: PART 1 · 사건 02 — "50만 줄 로그는, 읽지도 세지도 못합니다"

## 준비 (before/, after/ 각각에서)
```bash
python3 tools/make_log.py              # 50만 줄 (~45MB, 슬라이드와 동일 수치)
python3 tools/make_log.py --lines 50000   # 빠른 체험용
```
정답이 심겨 있다: **AssertionError 1,842 · TimeoutError 317 · 첫 급증 02:14**
(생성된 `logs/` 는 gitignore 대상)

## 체험 방법
1. **Before** — `before/` 에서 요청: `지난밤 logs/regression.log 원인 분석해줘`
   - ※ before 스킬에는 **재현 장치**가 들어 있다: "직접 읽고 직접 센다 · 스크립트 금지".
     요즘 에이전트는 시키지 않아도 알아서 코드를 만들어 집계하는데(그 우회가 바로 기법 ②다),
     그대로 두면 before 에서도 문제가 재현되지 않기 때문이다.
   - 관찰: 모델이 로그를 직접 READ → 대용량이라 일부만 읽고 추정하거나,
     읽은 범위 기준으로 집계 — 심어 둔 정답과 수치가 어긋나는지 확인해 보라.
2. **After** — `after/` 에서 같은 요청.
   - 관찰: 로그를 읽지 않고 `scripts/digest.py` 를 실행 → 요약 30줄만 근거로
     사용 → 수치가 1,842 / 317 / 02:14 와 정확히 일치하는지 확인.

## 관찰 포인트
- 읽기(용량)와 세기(능력) — Before는 두 번 실패하는 구조.
- After에서 원본이 500만 줄이 되어도 컨텍스트 비용은 여전히 요약 30줄.
- "수치는 스크립트 값 그대로" 규칙 — 세는 일은 코드가, 뜻을 읽는 일은 모델이.

**한 줄 정리 — 세는 일은 코드가.** 원본은 끝까지 밖에 두고, 계산이 끝난 결과만 들인다.
