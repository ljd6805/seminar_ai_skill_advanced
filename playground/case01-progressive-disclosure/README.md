# 사건 ① — 레퍼런스 계층화 (Progressive Disclosure)

> 슬라이드: PART 1 · 사건 01 — "스킬을 부를 때마다, 규칙 30페이지가 통째로 실립니다"

## 시나리오
컨벤션 리뷰 스킬이 규칙 전체를 SKILL.md 본문에 담고 있어, 발동할 때마다
규칙 전부가 컨텍스트에 로드된다. 이번 diff(`work/changes.diff`)는 스레드 코드
한 곳뿐이라 실제로 필요한 규칙은 동시성 한 편이다.

## 체험 방법
1. **Before** — `before/` 를 프로젝트 루트로 에이전트를 연다.
   - 요청: `work/changes.diff 컨벤션 리뷰해줘`
   - 관찰: 발동 시 SKILL.md 전체(규칙 3편 포함)가 통째로 로드된다.
     네이밍·예외 규칙까지 함께 실렸는지 확인해 보라.
2. **After** — `after/` 에서 같은 요청.
   - 관찰: SKILL.md(목차 역할)만 로드 → diff에서 thread/lock 감지 →
     `references/concurrency.md` **만** 추가로 읽고, §1.1 / §3.1 / §5.1 등
     조항 번호로 지적한다. naming.md 와 error-handling.md 는 끝까지 읽히지 않는다.

## 관찰 포인트
- 로드 단위: Before는 "전부 아니면 전무", After는 "목차는 늘, 본문은 그때만".
- After의 지적에 조항 번호(예: concurrency §3.1)가 붙는지 — "읽은 규칙만으로 지적" 규칙.
- 규칙이 늘어나도(파일 추가) After의 SKILL.md 는 그대로라는 점.

> 체험용이라 규칙을 각 30~40줄로 줄였다. 실제 사건은 30페이지(+38k 토큰)였고,
> 해결 후 로드는 3.3k 토큰(1/11)이 됐다.

**한 줄 정리 — 목차만 싣고, 지식은 문 뒤에.** 지식 비용이 보유량이 아니라 사용량에 비례하게 된다.
