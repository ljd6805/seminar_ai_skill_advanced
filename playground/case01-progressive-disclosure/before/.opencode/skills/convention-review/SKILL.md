# Convention Review

## 절차
1. 변경된 diff를 읽는다.
2. 아래 규칙에 따라 위반을 지적한다.

## 규칙 — 전체 수록


### 1. 네이밍 규칙 (8쪽 분량이던 문서)

#### §1. 케이스 규칙
- §1.1 클래스는 PascalCase. (예: `MetricsWorker`)
- §1.2 함수·메서드·변수는 snake_case. (예: `drain_loop`)
- §1.3 모듈 수준 상수는 UPPER_SNAKE_CASE. (예: `MAX_RETRY`)
- §1.4 모듈(파일)명은 snake_case 단수형. (예: `metrics_worker.py`)

#### §2. 의미 규칙
- §2.1 불리언은 is_/has_/can_ 접두. (예: `is_ready`)
- §2.2 컬렉션은 복수형 또는 _list/_map 접미. (예: `pending_jobs`)
- §2.3 단위가 있는 값은 단위를 접미로. (예: `timeout_sec`, `size_mb`)
- §2.4 콜백·핸들러는 on_/handle_ 접두. (예: `on_message`)

#### §3. 약어 규칙
- §3.1 허용 약어: id, db, api, url, cfg. 그 외 약어 금지.
- §3.2 두 글자 약어도 케이스 규칙을 따른다. (`HttpApi` — `HTTPAPI` 금지)

#### §4. 금지 사항
- §4.1 한 글자 이름은 인덱스(i, j)와 예외(e) 외 금지.
- §4.2 `data`, `info`, `tmp`, `manager` 등 무의미 이름 금지.
- §4.3 이름에 타입을 중복 표기하지 않는다. (`user_dict` ✕ → `users_by_id`)
- §4.4 부정형 불리언 금지. (`is_not_ready` ✕ → `is_ready` 반전 사용)


### 2. 예외 처리 규칙 (11쪽 분량이던 문서)

#### §1. 잡는 범위
- §1.1 `except Exception:` 광범위 캐치는 프로세스 경계(메인 루프, 요청 핸들러)에서만 허용.
- §1.2 `except: pass` 전면 금지 — 최소한 로그를 남긴다.
- §1.3 복구 계획이 없는 예외는 잡지 않고 전파한다.

#### §2. 도메인 오류
- §2.1 외부로 나가는 오류는 도메인 오류 코드로 변환한다. (예: `PAY-4102`)
- §2.2 오류 코드 표는 `docs/error-codes.md` 를 단일 출처로 삼는다.
- §2.3 스택 트레이스를 사용자 메시지에 노출하지 않는다.

#### §3. 로깅
- §3.1 예외 로그는 ERROR 레벨 + `exc_info=True`.
- §3.2 같은 원인의 예외를 루프 안에서 반복 로깅하지 않는다 (샘플링).
- §3.3 로그 메시지에 요청 식별자(request_id)를 포함한다.

#### §4. 재시도
- §4.1 재시도는 멱등 연산에만 허용한다.
- §4.2 고정 간격 재시도 금지 — 지수 백오프 + 상한.
- §4.3 재시도 횟수는 설정값으로 두고 하드코딩하지 않는다.

#### §5. 자원 정리
- §5.1 파일·소켓·락은 `with` 또는 `try/finally` 로 해제를 보장한다.
- §5.2 예외 경로에서도 큐·버퍼를 비우는 종료 절차를 둔다.


### 3. 동시성 규칙 (11쪽 분량이던 문서)

#### §1. 락 범위
- §1.1 락 안에서는 공유 상태의 읽기/쓰기만 한다 — I/O·sleep·네트워크 호출 금지.
- §1.2 락 보유 구간은 짧게 — 계산은 락 밖에서 마치고 결과만 반영한다.
- §1.3 락은 항상 `with lock:` 문으로 잡는다 (수동 acquire/release 금지).

#### §2. 공유 상태
- §2.1 스레드 간 공유 상태는 명시적으로 표시하고 소유자를 정한다.
- §2.2 공유 가변 상태보다 `queue.Queue` 등 메시지 전달을 우선한다.

#### §3. 원자성
- §3.1 락 없는 공유 카운터 증가(`count += 1`) 금지 — `+=` 는 원자적이지 않다.
- §3.2 검사-후-행동(check-then-act)은 하나의 락 구간 안에서 수행한다.
- §3.3 복합 갱신(읽고-계산하고-쓰기)은 단일 임계 구역으로 묶는다.

#### §4. 데드락 예방
- §4.1 락을 두 개 이상 잡을 때는 전역 순서를 문서화하고 지킨다.
- §4.2 락을 잡은 채 콜백·외부 코드를 호출하지 않는다.

#### §5. 스레드 생명주기
- §5.1 스레드는 종료 신호(Event 등)와 `join()` 경로를 함께 설계한다.
- §5.2 데몬 스레드는 버려도 되는 작업에만 사용하고 사유를 주석으로 남긴다.
- §5.3 스레드 수는 설정값으로 두고, 무한정 생성하지 않는다.

#### §6. async 혼용
- §6.1 async 코드에서 블로킹 호출 금지 — `run_in_executor` 로 우회한다.
- §6.2 이벤트 루프 객체를 스레드 간에 공유하지 않는다.
