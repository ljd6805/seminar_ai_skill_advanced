# 사건 ⑪ — 반박 검증 (Adversarial Check)

> 슬라이드: PART 3 · 사건 11 — "그럴듯한 결론이 검증을 통과해 버립니다"

## 시나리오
"8/12 배포가 오류를 처음 발생시켰다"라는 그럴듯한 결론. 지지 증거(배포 직후 오류 급증)만 모으면
통과한다. 하지만 `logs/service.log` 에는 **8/10(배포 전)에 이미** 동일한
CertificateError+TimeoutError 가 다수 있다. 교육용 데이터에서 인증서 만료를 대안 후보로 확인할 수 있다. `data/deploy-history.md`(8/12 13:00 v4.7 배포)가
"배포 탓"이라는 그럴듯한 결론을 유도한다. (로그·데이터는 before/·after/ 양쪽에 있다)

## 먼저 로그로 반례 확인 (before/ 또는 after/ 안에서)
```bash
grep ERROR logs/service.log | grep -oE "2026-08-[0-9]+" | sort | uniq -c
# → 08-10, 08-11 에도 ERROR 다수 (배포 8/12 이전!)
grep "2026-08-10" logs/service.log | grep CertificateError | head
```

## 체험 방법
1. **Before** — `before/` root-cause: "지지 증거를 모은다"까지.
   - `logs/service.log 와 data/deploy-history.md 로 장애 원인 분석해줘`
   - 배포(8/12 13:00) 직후 오류 폭증이 지지 증거로 쌓여 "8/12 배포" 결론으로 기운다.
2. **After** — `after/` refute-check: "이 결론은 틀렸다" 전제로 3경로 반박.
   - `"8/12 배포가 오류를 처음 발생시켰다" 결론을 반박 검증해줘`
   - 관찰: 시간 반박(grep 8/10~8/12) → 8/10 명제와 직접 모순되는 반례 발견 → **최초 발생 가설 기각** →
     대안 반박으로 인증서 만료 재조사 → 정정 보고 + 반박 기록 첨부.

## 관찰 포인트
- 검증의 방향이 "통과 찾기"에서 **"반례 찾기"**로 뒤집히는가.
- 지지 증거는 아무리 쌓여도 확증이 아니고, 명제와 직접 모순되는 반례인지 확인해야 한다.
- 리뷰 루프(⑩)가 "빠진 것"을 찾는다면, 반박 검증은 **"틀린 것"**을 찾는다.

**한 줄 정리 — 무너뜨려 보라.** 반박 결과와 조사 한계를 함께 보고한다.

## v0.9 검토 기준

배포 전 동일 오류는 “배포가 최초 발생 원인”이라는 명제를 반박한다. 배포가 악화에 기여했는지는 별도 조사한다. 세 경로에서 반례를 못 찾으면 잠정 가설, 자료 부족은 판단 보류로 기록한다.
