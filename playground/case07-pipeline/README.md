# 사건 ⑦ — 파이프라인 스킬 (Pipeline Orchestrator)

> 슬라이드: PART 2 · 사건 07 — "프로세스가 시니어의 머릿속에만 있습니다"

## 시나리오
부품 스킬 4개(log-digest·root-cause·incident-report·report-check)는 다 있는데,
"수집 → 분석 → 초안 → 검증"의 **순서와 완료 조건**을 적은 파일이 없다.
새벽 2시의 신입은 분석을 건너뛰고 리포트부터 만들어 재작업을 부른다.

## 체험 방법
1. **Before** — `before/` 에는 부품 4개만 있다.
   - `로그 요약해줘` → 되고, 그다음 무엇을 할지는 사람이 지시해야 한다.
   - `일단 리포트 만들어줘` 처럼 분석을 건너뛰면 그대로 진행되는지 관찰.
2. **After** — `after/` 에는 지휘자 `incident-flow` 가 추가돼 있다.
   - `장애 대응 시작해줘` — 한 마디.
   - 관찰: incident-flow 의 단계표대로 1→2→3→4 자동 진행, 각 단계가
     `output/*.md` 산출물을 남기며 "단계명 + 경로" 한 줄씩 보고.
   - 재개 실험: `output/digest.md` 와 `output/analysis.md` 만 남기고 다시 시작하면
     1·2단계를 건너뛰고 **3단계부터** 재개하는지 확인(사건 ③ 원리).

## 관찰 포인트
- 사람의 개입이 **첫 한 마디**로 줄어드는가.
- 단계를 잇는 화살표가 사건 ⑥의 **산출물 약속**(파일 경로)이라는 점.
- 순서가 사람 머릿속이 아니라 **incident-flow 의 단계표(파일)**에 있다.

**한 줄 정리 — 프로세스도 스킬이다.** 시니어의 머릿속 순서가 기록된 자산이 된다.
