# Incident Flow — 조율 스킬(지휘자)

## 단계 — 순서 고정 · 산출물 없으면 다음 단계 금지
1. 수집  → log-digest 스킬      → `output/digest.md`
2. 분석  → root-cause 스킬      → `output/analysis.md`
3. 초안  → incident-report 스킬 → `output/report.md`
4. 검증  → report-check 스킬    → `output/verdict.md`

## 진행 규칙
- 각 단계 완료 시 **단계명과 산출물 경로만 한 줄** 보고한다.
- 이전 산출물의 SCHEMA·RUN·SOURCE와 입력 산출물 해시, 해당 단계의 검증 결과가 현재 요청과 일치할 때만 재사용한다. 파일 존재만으로 건너뛰지 않는다.
  입력이 바뀌거나 검증되지 않았으면 해당 단계와 그 결과에 의존하는 후속 단계를 다시 실행한다.
- 단계 실패 시: 실패 지점과 사유를 보고하고 멈춘다.

## 금지
- 단계 건너뛰기 · 순서 변경 · 산출물 없이 "완료" 보고

## 실행 경계
이 문서는 순서를 지시한다. 자동 실행·단계 차단·재시도는 호출 실행기나 훅에서 별도로 구현해야 한다. 예제에 범용 실행기는 포함되지 않는다. 실패 원인 보완 후 최대 2회 재시도하고, 계속 실패하면 원인과 산출물을 남기고 중단한다.

## 산출물 계약
시작 시 현재 작업의 RUN과 원본 로그 SHA-256을 정한다. 모든 산출물에 SCHEMA: 1, RUN, SOURCE를 기록하며, 소비한 직전 산출물의 SHA-256도 INPUT 필드에 기록한다. 값은 실제 파일에서 계산한다. 검증 결과도 검증한 파일 해시와 함께 보존한다.
