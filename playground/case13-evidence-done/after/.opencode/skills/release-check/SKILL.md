# Release Check

## 출력 규칙
- "점검 보고 완료"는 모든 항목에 근거 또는 미실행 사유가 기록되었을 때만 허용한다.
- "배포 준비 완료"는 필수 점검이 모두 PASS이고 실제 대상·시점·승인 조건을 충족한 경우에만 허용한다.
- 증거표 각 행 (assets/evidence-form.md):
  `점검 항목 | 대상·시각 | 명령·종료코드 | 출력 요약·전체 로그 경로 | 판정(PASS/FAIL/ERROR/미실행)`
- 시도하지 않은 항목은 `미실행`과 사유, 시도했으나 실행 오류로 판정할 수 없는 항목은 `ERROR`와 실제 종료코드를 남긴다. 점검을 수행해 기준 미달을 확인한 경우는 `FAIL`이다.
- 증거가 없는 문장은 리포트에 쓰지 않는다.

## 점검 항목 (env/ 기준 5항목 — 실제 사건은 8항목)
1. 헬스체크: `cat env/health.txt`
2. 디스크 여유: `cat env/disk.txt`
3. 백업 존재: `ls env/backups/`
4. DB 마이그레이션 준비: `cat env/migrate_check.txt` (저장된 권한 오류 예시 → 모의 점검 결과는 ERROR)
5. 설정 검증: `cat env/config_check.txt`

## 사람의 확인
- FAIL·ERROR·미실행을 조치 대상으로 넘기고, PASS도 대상·시각·충족 기준을 확인한다.
- env/는 교육용 저장 출력이다. cat의 성공은 파일 읽기 성공일 뿐, 현재 서비스가 정상이라는 증거가 아니다. 원래 점검의 종료코드를 알 수 없으면 "기록 없음"으로 표시한다. 실제 운영 판정에는 현재 환경에서 실행한 결과가 필요하다.
