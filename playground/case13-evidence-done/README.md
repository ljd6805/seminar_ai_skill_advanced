# 사건 ⑬ — 증거 기반 완료 (Evidence-based Done)

> 슬라이드: PART 3 · 사건 13 — "'이상 없습니다'라는 말은 증거가 아닙니다"

## 시나리오
배포 전 점검(실제 사건은 8항목, 체험은 5항목으로 축약)을 "완료 — 이상 없습니다" 한 줄로 보고. 실은 4번(DB 마이그레이션)이
권한 오류로 **실행 실패**했는데 낙관적으로 뭉개졌고, 배포 후 그 항목이 장애를 냈다.
여기 `env/migrate_check.txt` 에 그 권한 오류가 심겨 있다. (env/ 는 before/·after/ 양쪽에 있다)

## 체험 방법
1. **Before** — `before/` release-check: 실행 기록 없이 "이상 없습니다" 한 줄.
   - `env/ 기준으로 배포 전 점검해줘` → 4번의 실패가 문장 속에 묻히는지 관찰.
     사람은 실행 근거가 없어 점검을 다시 확인해야 한다.
2. **After** — `after/` release-check: 증거표(`assets/evidence-form.md`) 의무.
   - 같은 요청 → 각 행에 **실행한 명령 + 출력 원문 + 판정** 을 채운다.
   - 관찰: 4번은 권한 오류(errno 13)이므로 저장된 점검의 판정이 **"ERROR"** + 사유로 정직하게 남는지.
     증거 없는 주장은 리포트에 못 쓴다.

## 관찰 포인트
- 완료의 정의가 **주장**에서 **검증 가능한 기록**으로 바뀌는가.
- "미실행"이 숨겨지지 않고 정보로 남는가 — 사람의 재확인 대상을 좁힐 수 있다(시간 단축은 미측정).
- 3편의 Record 개념을 산출물에 적용한 것.

**한 줄 정리 — 증거 없으면 미완료.** 완료 선언에는 증거표를 반드시 붙인다.

## v0.9 검토 기준

점검 보고 완료와 배포 준비 완료를 구분한다. 실행 오류는 ERROR, 미시도는 미실행이다. env/는 저장된 교육용 출력이며 cat의 성공을 실제 서비스의 정상 판정으로 사용할 수 없다.
