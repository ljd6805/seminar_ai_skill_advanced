# 사건 ③ — 외부 기억 (External Memory)

> 슬라이드: PART 1 · 사건 03 — "작업이 3시간을 넘어가면, 에이전트는 첫 결정을 잊습니다"

## 시나리오
모듈 8개(체험용, 실제는 40개)를 전부 v2 API 로 통일하는 마이그레이션.
첫 결정("v2 통일")이 대화에만 있으면, 대화가 길어지거나 세션이 끊길 때 증발한다.

## 체험 방법 — Before (기억이 대화에만 있을 때)
1. `before/` 에서: `src/ 모듈들을 전부 v2 API로 통일해줘` (v2 규칙은 임의로 안내)
2. 두어 개 진행한 뒤 **세션을 새로 열고** `이어서 해줘` 라고만 해 보라.
   - 관찰: 무엇을 하던 작업인지, 규칙이 v2였는지 — 대화가 사라지면 재개 불가.

## 체험 방법 — After (기억을 파일에 둘 때)
1. `after/` 에는 이미 `output/state.md` 가 **03에서 끊긴 상태**로 놓여 있다
   (01·02 완료, 다음 03). 첫 결정과 메모가 파일에 살아 있다.
2. **빈 컨텍스트의 새 세션**에서: `이어서 해줘`
   - 관찰: 에이전트가 state.md 를 먼저 읽고 "03번 모듈부터 v2로 재개"한다.
     `src/payment_client.py` 를 v2 규칙(SKILL.md 참조)으로 고치고,
     state.md 의 03 줄을 `[x]` 로 바꾸며 메모 1줄을 남기는지 확인.
3. 처음부터 시작하려면 `output/state.md` 를 지우면 template 로 새로 만든다.

## 관찰 포인트
- 지난 대화 없이도 재개되는가 — "대화는 흘러가고, 파일은 남는다".
- 갱신이 모듈마다 즉시 일어나는가 (state.md 의 `[x]` 와 메모).
- state.md 는 인수인계 문서로도 그대로 읽힌다.

**한 줄 정리 — 파일은 남는다.** 기억을 휘발되는 컨텍스트에서 영속되는 파일로.
