## 2. 핵심 메시지 (한 문장)

> **스킬 하나는 절차를 담고, 스킬 시스템은 한계를 설계한다 — 256k는 벽이 아니라 설계 조건이다.**

부제: 컨텍스트에는 필요한 근거와 요약을, 스킬 사이에는 약속을.

## 3. 전개 원칙 — 이 세션이 지키는 네 가지 규칙

1. **사건 서사로 진행한다.** 기법마다 네 장 — **문제 장**(문제 예시 재현 → 문제제기 → 문제의 스킬 원문 → 원인 분석), **해결 장**(해결 리플레이 → 해결된 스킬 발췌 → 기술소개), **원리 장**(기법의 작동 원리를 움직이는 다이어그램 한 장으로 — 스킬이 처음인 청중이 여기서 따라잡는다), **Before/After 장**(고치기 전·후의 SKILL.md **전문(全文)** 대조 — 스킬북의 본편). **기법의 이름은 항상 해결 장 마지막에, 답으로서 등장한다** (문제 주도형 전개).
2. **모든 예시는 재현 가능한 형태로.** 교육용 요청·실패 로그·가정 수치를 사용하고, **문제 장에는 문제를 재현하는 SKILL.md 원문을, 해결 장에는 교정된 참고 SKILL.md를** 나란히 싣는다 — 세미나 자료이자 스킬북으로 쓰기 위함이다.
3. **글보다 그림.** 문제·해결은 터미널 리플레이 애니메이션으로, 원인은 게이지·차트로, 기법의 작동 원리는 원리 장의 씬 다이어그램(목차와 본문·검문 게이트·창 분할 등 사건마다 다른 은유)으로. 산문 블록은 장당 3줄 이내(캡션·note)로 제한한다.
4. **발표 장수와 자료 장수를 구분하지 않는다.** 레이어·모드 없이 55장 단일 흐름 — 모든 장이 발표 장이자 읽기 자료다.

## 4. 전체 전개 구조

```text
2편 다섯 이론 1장 복습
        ↓
잘 만든 스킬이 막히는 두 장면 (2분할 터미널 목격) → 문제 2 도출 · 256k 가계부 체감 · 진행 방식 안내
        ↓
PART 1 · 컨텍스트 절약술 — 사건 ①~⑤  (사건마다 [문제 → 해결 → 원리 → Before/After])
PART 2 · 스킬 연계술   — 사건 ⑥~⑨ + "연결의 네 질문" 정리 + 결합 데모(파이프라인 시네마)
                          ※ 네 사건은 하나의 장애 대응 프로세스를 이어서 완성하는 연작 —
                            ⑥ 무엇을 주고받나(전달) · ⑦ 다음 순서는(지휘) · ⑧ 시작해도 되나(완결성) · ⑨ 누가 나서나(입구)
                            (연결을 먼저 고정하고 → 그 연결들로 라인을 세우고 → 파일의 속이 채워졌는지 검사하고 → 스킬이 불어나면 입구를 정리한다)
                        + "하나의 흐름" 정리(P1 부품 → P2 라인 연계)
        ↓
기법 선택 지도 → 종합 사례(기법 6개 중첩) → 실습 예고 → 마무리 → 부록 요약표
```

## 5. 사건 카탈로그 (9) — 문제 예시 → 원인 → 해결

### PART 1 · 컨텍스트 절약술 — "컨텍스트에는 필요한 근거와 요약을 들여보낸다"

| # | 사건(문제 예시) | 원인 분석 | 해결 → 기법 | 한 줄 |
|---|---|---|---|---|
| ① | 컨벤션 리뷰 한 번에 규칙 30페이지(+38k 토큰)가 통째로 로드 | 발동 시 본문 전체 로드 — 지식·절차가 한 파일이면 전부 아니면 전무 | 절차 40줄 + references/ 조건부 로드(+3.3k) → **레퍼런스 계층화** | 목차만 싣고, 지식은 문 뒤에 |
| ② | 로그 50만 줄 — 12%에서 읽기 중단, 집계는 오답 | 용량(수백만 토큰≫256k) + 능력(확률 모델은 세기에 약함) | digest.py가 밖에서 집계, 예시 요약 약 30줄과 필요한 원문 근거 확인 → **스크립트 위임** | 세는 일은 코드가 |
| ③ | 장기 마이그레이션 — 초반 결정 재확인 필요, 새 세션에 맥락이 자동 전달되지 않을 수 있음 | 핵심 상태가 대화에만 있음 — 요약·정리 방식은 설정에 따라 다르고 종료는 기록 전체 삭제와 다름 | state.md를 현재 코드·검증 결과와 대조 후 재개 → **외부 기억** | 파일은 남는다 |
| ④ | 설명 하나에 파일 9개 통째 읽다 파산 | 탐색 전략 부재 — 소비가 리포 크기에 비례 | tree→grep→±50줄, 총 297줄 → **지도 우선 탐색** | 읽기는 검색의 결과 |
| ⑤ | 모듈 12개 점검 — ①~④를 다 써도 6번째에서 한도 | 한 세션의 한도를 넘는 작업은 분할·상태 보존·재개 설계 필요 | 독립 컨텍스트에 분담, 약 10줄 요약과 상세 근거 회수 → **분업 요약** | 분담하고 근거를 연결한다 |

### PART 2 · 스킬 연계술 — "스킬은 대화가 아니라 파일로 협업한다"

| # | 사건(문제 예시) | 원인 분석 | 해결 → 기법 | 한 줄 |
|---|---|---|---|---|
| ⑥ | 요약을 리포트 스킬이 못 받아 사람이 복붙, 구버전 사고 | 결과가 대화에만 — 휘발·비정형·버전 없음, 인터페이스 미정의 (함수가 return 없이 print만 한 꼴) | 생산자·소비자의 조건 정의(경로·형식·RUN·SOURCE) — **기대값과 대조하며 형식 버전과 최신성을 구분** → **산출물 약속** | 약속이 있어야 부품 |
| ⑦ | 새벽 장애 — 신입이 분석 단계를 건너뜀, 순서는 시니어 머릿속 | 각 스킬은 자기 단계만 알고 순서·완료 조건은 미기록 | 요청 후 4단계 절차 안내, 자동 순서·차단은 실행기에서 구현 (산출물은 ⑥의 약속된 파일) → **파이프라인 스킬** | 프로세스도 스킬이다 |
| ⑧ | 경로·형식·입력 식별자만 확인한 부실 분석이 3·4단계까지 흘러 전량 재작업 | 약속은 조건 정의이고 실제 검사가 필요함 — 늦게 발견하면 후속 단계까지 재작업, 비용 배율은 미측정 | gate.py가 3섹션·최소 15자·미완성 표시를 검사, 호출 측은 FAIL이면 중단·반려 — **모든 사이가 아니라 부실이 비싸지는 길목에만(파이프라인에 1~2곳)** → **게이트 체크** | 약속은 파일의 겉(맞는 파일인가), 게이트는 파일의 속(시작할 수 있는가) |
| ⑨ | 스킬 20개 — "로그 봐줘"에 pdf-export 발동, 리뷰 정리는 미발동 | 모호한 description과 요청 해석 오류 — 늘수록 겹침과 구멍 증가 | qa-desk 접수 창구 + 분류표, 모호하면 질문 → **라우터 스킬** | 접수 창구를 세워라 |

v1.0에서 세미나 범위에서 제외했다(§9 결정 기록 참조). 자가 리뷰 루프·반박 검증·기계 채점 하네스·증거 기반 완료의 체험 키트는 `playground/case10~13`에 번외로 남아 있다.

## 7. 시간 배분 (발표 약 65분 기준)

| 구간 | 장 | 시간 |
|---|---|---|
| 도입 (복습 포함) | 1~7 | 9분 |
| PART 1 (사건 ①~⑤) | 8~29 | 25분 |
| PART 2 (사건 ⑥~⑨ + 정리·데모) | 30~48 | 20분 |
| 하나의 흐름 + 종합 (선택 지도 + 사례) | 49~51 | 7분 |
| 실습 예고 + 마무리 | 52~53 | 4분 |
| Q&A | 54 | 15분 |

PART 3를 제외하면서 사건당 시간을 약 2분 30초에서 **약 3분**으로 늘렸다 — 원리 장의 다이어그램에 30~40초를 쓰고, PART 2 데모(파이프라인 시네마)는 playground의 `case07`·`case08`로 실제 시연할 여지를 둔다. 문제 장에서 리플레이가 도는 동안 상황을 말로 잇고, 해결 장에서 리플레이 → 스킬구성 → 명명 순으로 짚은 뒤, **원리 장에서 다이어그램으로 "왜 통하는가"를 한 번 더 눌러 준다**(스킬 경험이 얕은 청중의 이해가 여기서 정렬된다). **Before/After 장은 발표에서는 10~20초로 "전문은 여기 있습니다"만 짚고 넘어가는 참고 장**이며, 세미나 후 스킬북으로 읽을 때의 본편이다. 시간이 밀리면 원리 장은 그림만 보여 주고 Before/After 장은 건너뛴다. 90분 대비 약 10분의 여유는 리허설에서 배분한다.

## 8. 실습 연계 계획 (미정 사항 명시)

- **확정**: 기존 `seminar_ai_skill_quest` 리포(데이터·채점기·보드)를 기반으로 심화 미션 트랙을 얹는다. 해결 장의 스킬구성이 미션 골격이 된다.
- **후보 미션**: 스크립트 위임(②) · 산출물 약속+파이프라인(⑥⑦) · 게이트 체크(⑧) · 라우터(⑨).
- **미정**: 미션 수, 레벨 체계, 일정. 확정 전까지 슬라이드에는 방향만 예고한다.


## 8.1 v0.9에서 명시한 적용 조건

- 256k는 이 자료의 환경 가정이다. 컴팩션 시점·보존 범위·스킬 선택은 모델과 실행 환경에 따라 달라진다. 사내 배포판의 상세 동작은 공개 문서만으로 확인할 수 없다.
- 리플레이·게이지·시간·비용은 교육용 예시다. 실측 토큰·시간·정확도 개선 결과가 아니다. 예시의 38k/256k=14.84%, 3.3k/256k=1.29%, 1k/256k=0.39%는 해당 가정의 산술이다.
- SKILL은 절차, 검사기는 구현된 조건의 판정, 실행기·훅은 호출 허용·차단을 담당한다. 예제는 범용 파이프라인 실행기를 제공하지 않는다.
- 48장 도해는 수집·분석·보고 세 단계만 표시한다. 실제 절차의 최종 검증(4단계)은 유지한다.
- PASS는 검사 범위에 한정한다. 형식 버전은 최신성, 반례 미발견은 인과관계 입증, 보고 작성 완료는 배포 준비 완료와 같지 않다.
- [논리 교정 내역·검증 범위·출처](logic-correction-report.html)를 함께 읽는다.
