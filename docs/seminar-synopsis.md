> **버전**: v0.3 (2026-08-21) — 사건 서사 개편
> **상태**: 논리 구조 확정, 슬라이드 v0.3 반영 완료

## 1. 세미나 메타 정보

| 항목 | 내용 |
|---|---|
| 시리즈 | AI Agent 세미나 4편 (1편 seminar_ai_agent · 2편 seminar_ai_skill_quest · 3편 seminar_ai_hook_harness_slide) |
| 이번 편 구성 | 이론편(본 문서) + 실습편(Skill Quest 심화 시즌, **방식 미정 — 별도 기획**) |
| 발표 시간 | 90분 목표 (발표 75분 + Q&A 15분) |
| 청중 | 팀 엔지니어 전원 — 2편(Skill Quest)으로 스킬 기초를 실습했고, 3편으로 Hook/Harness 개념을 접한 상태 |
| 환경 전제 | 사내 LLM은 **컨텍스트 256k** — 이 제약을 세미나 전체의 설계 조건으로 삼는다 |
| 도구 기준 | opencode (`.opencode/skills/<이름>/SKILL.md`) — 원리는 도구 중립으로 서술 |
| 예시 수준 | 팀 공용 소재(리그레션 로그, 테스트 리포트, 배포 점검, 장애 대응) — 2편 실습 리포의 데이터를 재사용해 실습 연계를 예비한다 |

## 2. 핵심 메시지 (한 문장)

> **스킬 하나는 절차를 담고, 스킬 시스템은 한계를 설계한다 — 256k는 벽이 아니라 설계 조건이다.**

부제: 컨텍스트에는 결론만, 스킬 사이에는 계약을, 완료에는 증거를.

## 3. 전개 원칙 — 이 세션이 지키는 네 가지 규칙 (v0.3)

1. **사건 서사로 진행한다.** 기법마다 세 장 — **문제 장**(문제 예시 재현 → 문제제기 → 문제의 스킬 원문 → 원인 분석), **해결 장**(해결 리플레이 → 해결된 스킬 발췌 → 기술소개), **개조 명세 장**(Before/After 스킬 **전문(全文)** 대조 + 핵심 변경 요약 — 스킬북의 본편). **기법의 이름은 항상 해결 장 마지막에, 답으로서 등장한다** (3편의 문제 주도형 전개 계승).
2. **모든 예시는 실제 형태로.** 실제 요청 문장, 실제 실패 로그, 실제 수치로 재현하고, **문제 장에는 문제가 되는 스킬의 당시 SKILL.md 원문을, 해결 장에는 해결된 스킬의 실제 작성 형태를** 나란히 싣는다 — 세미나 자료이자 스킬북으로 쓰기 위함이다.
3. **글보다 그림.** 문제·해결은 터미널 리플레이 애니메이션으로, 원인은 게이지·차트·구조 다이어그램으로. 산문 블록은 장당 3줄 이내(원인 캡션·note)로 제한한다.
4. **발표 장수와 자료 장수를 구분하지 않는다.** 레이어·모드 없이 62장 단일 흐름 — 모든 장이 발표 장이자 읽기 자료다.

## 4. 전체 전개 구조

```text
2편 다섯 이론 1장 복습
        ↓
잘 만든 스킬이 막히는 세 장면 (3분할 터미널 목격) → 문제 3+1 도출 · 256k 가계부 체감 · 진행 방식 안내
        ↓
PART 1 · 컨텍스트 절약술 — 사건 ①~⑤  (사건마다 [문제 장 → 해결 장])
PART 2 · 스킬 연계술   — 사건 ⑥~⑨ + 결합 데모(파이프라인 시네마)
PART 3 · 검증·리뷰 하네스 — 사건 ⑩~⑬ + 네 겹 그물 정리
PART 4 · 확산          — 사건 ⑭
        ↓
기법 선택 지도 → 종합 사례(기법 7개 중첩) → 실습 예고 → 마무리 → 부록 요약표
```

## 5. 사건 카탈로그 (14) — 문제 예시 → 원인 → 해결

### PART 1 · 컨텍스트 절약술 — "컨텍스트에는 결론만 들여보낸다"

| # | 사건(문제 예시) | 원인 분석 | 해결 → 기법 | 한 줄 |
|---|---|---|---|---|
| ① | 컨벤션 리뷰 한 번에 규칙 30페이지(+38k 토큰)가 통째로 로드 | 발동 시 본문 전체 로드 — 지식·절차가 한 파일이면 전부 아니면 전무 | 절차 40줄 + references/ 조건부 로드(+3.3k) → **레퍼런스 계층화** | 목차만 싣고, 지식은 문 뒤에 |
| ② | 로그 50만 줄 — 12%에서 읽기 중단, 집계는 오답 | 용량(수백만 토큰≫256k) + 능력(확률 모델은 세기에 약함) | digest.py가 밖에서 집계, 요약 30줄만 입장 → **스크립트 위임** | 세는 일은 코드가 |
| ③ | 3시간 마이그레이션 — 첫 결정(v2 통일)을 잊고, 세션 종료로 전부 증발 | 기억이 대화에만 — 컴팩션은 앞부터, 종료는 전부 삭제 | state.md 읽고 27번부터 재개 → **외부 기억** | 파일은 남는다 |
| ④ | 설명 하나에 파일 9개 통째 읽다 파산 | 탐색 전략 부재 — 소비가 리포 크기에 비례 | tree→grep→±50줄, 총 297줄 → **지도 우선 탐색** | 읽기는 검색의 결과 |
| ⑤ | 모듈 12개 점검 — ①~④를 다 써도 6번째에서 한도 | 절약은 소비 감소일 뿐, 총량은 1×256k 고정 | 워커 N개에 위임, 10줄 보고만 회수 → **분업 요약** | 쪼개면 곱해진다 |

### PART 2 · 스킬 연계술 — "스킬은 대화가 아니라 파일로 협업한다"

| # | 사건(문제 예시) | 원인 분석 | 해결 → 기법 | 한 줄 |
|---|---|---|---|---|
| ⑥ | 요약을 리포트 스킬이 못 받아 사람이 복붙, 구버전 사고 | 결과가 대화에만 — 휘발·비정형·버전 없음, 인터페이스 미정의 | 출력 계약(경로+형식+버전 표시)과 입력 계약 → **산출물 계약** | 계약이 있어야 부품 |
| ⑦ | 새벽 장애 — 신입이 분석 단계를 건너뜀, 순서는 시니어 머릿속 | 각 스킬은 자기 단계만 알고 순서·완료 조건은 미기록 | "장애 대응 시작" 한 마디로 4단계 자동 진행 → **파이프라인 스킬** | 프로세스도 스킬이다 |
| ⑧ | 스킬 20개 — "로그 봐줘"에 pdf-export 발동, 리뷰 정리는 미발동 | description 유사도 경쟁 — 늘수록 겹침과 구멍 증가 | qa-desk 접수 창구 + 분류표, 모호하면 질문 → **라우터 스킬** | 접수 창구를 세워라 |
| ⑨ | 부실 분석이 3·4단계까지 흘러 전량 재작업 | 단계 간 검문 부재 — 발견이 늦을수록 수정 비용 증폭(1×→3×→9×) | gate.py FAIL이면 진행 거부·반려 → **게이트 체크** | 게이트가 흐름을 지킨다 |

### PART 3 · 검증·리뷰 하네스 — "'됐습니다'를 '증명됐습니다'로"

| # | 사건(문제 예시) | 원인 분석 | 해결 → 기법 | 한 줄 |
|---|---|---|---|---|
| ⑩ | "괜찮아?"에 항상 "네" — 사람 리뷰에서 매번 3건 지적 | 같은 컨텍스트·같은 프레임 — 자기 출력 정당화, 기준 없는 검토는 인상 평가 | 역할 전환 + checklist.md, 지적 0건까지 → **자가 리뷰 루프** | 같은 모델, 다른 프레임 |
| ⑪ | "원인은 8/12 배포" 통과 → 롤백 헛수고, 실제는 인증서 만료 | 확증 편향 — 지지 증거만 수집, 반례 탐색이 절차에 없음 | "틀렸다" 전제로 3경로 반박, 반례 발견 시 기각 → **반박 검증** | 무너뜨려 보라 |
| ⑫ | 합계 불일치를 "다시 확인해줘"로 못 잡음 — 사람이 검산기 | 결정적 기준(형식·산술)을 확률 도구(LLM)로 검사 — 도구 불일치 | validate.py 채점 루프, PASS까지 수정·로그 첨부 → **기계 채점 하네스** | 채점으로 통과하라 |
| ⑬ | "이상 없습니다" → 배포 → 장애, 실은 4번 항목 실행 실패였음 | 완료 보고가 주장문 — 실행 여부·출력이 안 남아 확인·반박 불가 | 증거표(명령+출력+판정) 의무, 미실행 정직 표기 → **증거 기반 완료** | 증거 없으면 미완료 |

## 7. 시간 배분 (75분 발표 기준)

| 구간 | 장 | 시간 |
|---|---|---|
| 도입 (복습 포함) | 1~7 | 10분 |
| PART 1 (사건 ①~⑤) | 8~24 | 22분 |
| PART 2 (사건 ⑥~⑨ + 데모) | 25~38 | 17분 |
| PART 3 (사건 ⑩~⑬ + 그물) | 39~52 | 17분 |

사건당 약 2분 — 문제 장에서 리플레이가 도는 동안 상황을 말로 잇고, 해결 장에서 리플레이 → 스킬구성 → 명명 순으로 짚는다. **개조 명세 장은 발표에서는 10~20초로 "전문은 여기 있습니다"만 짚고 넘어가는 참고 장**이며, 세미나 후 스킬북으로 읽을 때의 본편이다.

## 8. 실습 연계 계획 (미정 사항 명시)

- **확정**: 기존 `seminar_ai_skill_quest` 리포(데이터·채점기·보드)를 기반으로 심화 미션 트랙을 얹는다. 해결 장의 스킬구성이 미션 골격이 된다.
- **후보 미션**: 스크립트 위임(②) · 산출물 계약+파이프라인(⑥⑦) · 채점 루프(⑫) · 반박 검증(⑪).
- **미정**: 미션 수, 레벨 체계, 일정. 확정 전까지 슬라이드에는 방향만 예고한다.
