## 2. 핵심 메시지 (한 문장)

> **기초 시즌이 "스킬 하나를 만드는 퀘스트"였다면, 심화 시즌은 "스킬 시스템을 조립하는 퀘스트"다.**

부제: 부품을 다듬고(P1), 라인을 세우고(P2), 검사를 통과하라(P3). — 이론 67장 "하나의 흐름"의 세 레인이 그대로 시즌의 세 스테이지가 된다.

## 3. 설계 원칙 — 이 실습이 지키는 다섯 가지 규칙

1. **해결 장이 곧 미션 골격.** 각 미션의 성공 조건은 이론편 해결 장·Before/After 장의 스킬 구성(경로·형식·마커·금지·검증)을 그대로 채점 항목으로 옮긴 것이다. 미션을 깨면 스킬북(Before/After 장)의 After가 손에 남는다.
2. **무대는 전부 재사용.** 리포·데이터·채점기·보드는 2편 것을 확장만 한다. 특히 **2편에서 참가자가 직접 만든 스킬(log-digest, test-report)이 심화 미션의 주인공으로 재등장**한다 — "그때 그 스킬이 데이터가 커지자 다시 막힌다"가 시즌 2의 오프닝 서사다.
3. **파이썬은 주고, 스킬을 쓰게 한다.** digest.py·gate.py·validate.py 등 스크립트는 뼈대(또는 완성본)를 리포가 제공한다. 참가자의 노동은 코딩이 아니라 **SKILL.md 설계** — 절차·약속·금지·검증을 적는 일이다. (예외: M4는 validate.py의 채점 규칙 3곳을 직접 채운다 — 채점기를 만드는 경험 자체가 미션이므로)
4. **채점기가 곧 교보재.** 미션마다 돌리는 `check.sh`가 바로 기법 ⑫(기계 채점 하네스)의 실물임을 브리핑과 미션 카드에서 반복해 상기시킨다 — 이론 슬라이드의 문장 "2편 실습의 check.sh가 바로 이 구조였습니다"를 실습 전체의 러닝 개그로 쓴다.
5. **이론과 같은 사건 서사.** 미션 카드는 문제 상황 재현으로 시작한다. 기법 이름은 이론편에서 이미 배웠으므로 카드가 숨기지 않고 **사건 번호·기법 이름을 명시해 복습 고리**로 쓴다 — "이름은 답으로서 마지막에"는 이론편의 리듬이고, 실습의 리듬은 "배운 이름을 손으로 확인"이다. 보드 리캡은 클리어 후 원리를 한 번 더 굳힌다.
6. **초심자 가드레일.** (a) 신규 스킬은 전부 **템플릿 빈칸 채우기** — 백지 작성 없음. (b) 카드의 지시문·교체 텍스트는 **복붙 가능한 형태**로 제공. (c) 함정(주차 CSV·TBD 분석·그럴듯한 결론)은 참가자가 아니라 **게이트·채점기가 잡는다** — 참가자는 FAIL 메시지를 따라가면 풀리고, 그 FAIL 경험 자체가 학습 이벤트다. (d) 채점기의 fail 메시지는 다음 행동을 알려주는 문장으로 쓴다. (e) 힌트는 카드에 동봉(접힘)하고 15분 경과 시 열도록 안내한다.

## 4. 시즌 구조 — 3 스테이지 · 6 레벨 (+자율 퀘스트)

```text
STAGE 1 · 부품     Lv.8            사건 ② — 다시 고장난 log-digest (스크립트 위임)
        ↓
STAGE 2 · 라인     Lv.9 ~ Lv.10    사건 ⑥ — 전달 사고 (산출물 약속)
                                   사건 ⑦+⑧ — 새벽 2시 훈련 (파이프라인 + 게이트 1곳)
        ↓
STAGE 3 · 검사     Lv.11 ~ Lv.12   사건 ⑫ — 검산기 은퇴식 (기계 채점 하네스)
                                   사건 ⑪ — 그럴듯한 오답 (반박 검증)
        ↓
FINAL  · 보스전    Lv.13           종합 사례 — 주간 리그레션 리포트 (기법 7중첩 + ⑬ 증거표)
        ↓
EX     · 자율 퀘스트               내 업무를 라인으로 — 2편 Lv.7에서 만든 "내 스킬"을 파이프라인으로 확장
```

| 레벨 | 랭크(안) | 미션 id | 사건 · 기법 | 세미나 내 |
|---|---|---|---|---|
| Lv.8 | 부품공 | `adv-script-offload` | ② 스크립트 위임 | ✅ M1 |
| Lv.9 | 연결공 | `adv-artifact-contract` | ⑥ 산출물 약속 | ✅ M2 |
| Lv.10 | 라인 지휘자 | `adv-pipeline` | ⑦ 파이프라인 (+⑧ 게이트 1곳) | ✅ M3 |
| Lv.11 | 채점관 | `adv-validate-loop` | ⑫ 기계 채점 하네스 | ✅ M4 |
| Lv.12 | 반증관 | `adv-refute` | ⑪ 반박 검증 | ✅ M5 |
| Lv.13 | 라인 마스터 🏭 | `adv-final-weekly` | 종합(⑨⑦②①⑧⑫⑬ 중 7기법) | 세미나 후 보스전 (수료는 Lv.12) |
| EX | 도감 등록 | `adv-my-pipeline` | 자기 업무 적용 | 자율 (2편 Lv.7과 같은 위상) |

- **수료 라인은 Lv.12** (2편의 "수업은 Lv.6까지" 관례 계승). Lv.13 보스전과 EX는 세미나 후 각자 도전하며, 클리어 시 보드 도감에 기록된다.
- 미션 1개 = 레벨 1개. 성장 코드 체계(`GROW-L8-XXXX` ~)는 2편 `check.sh`의 `sha256(id+salt)` 로직을 그대로 쓰므로 **미션 id만 확정되면 코드는 자동 발급**된다 (salt 변경 없음).

### 다루지 않는 기법과 이유 (미션 카드·클로징에서 한 줄씩 안내)

| 기법 | 제외 이유 | 보완 |
|---|---|---|
| ① 레퍼런스 계층화 | 2편 Lv.5(번들+REF-VERSION)에서 이미 실습함 | 보스전에서 quality-bar.md 재사용으로 자동 복습 |
| ③ 외부 기억 | 단독 미션으로는 "3시간 작업" 재현 불가 | M3의 중간 재개 규칙(산출물 있으면 건너뜀)으로 맛보기 |
| ④ 지도 우선 탐색 | 실습 리포가 작아 체감 불가 | 이론 Before/After 장을 스킬북으로 안내 |
| ⑤ 분업 요약 | 사내 opencode 버전·설정별 서브에이전트 기능 편차 (시놉시스 결정 기록 계승) | 이론 장 안내 + 추후 환경 통일 시 EX 미션 후보 |
| ⑨ 라우터 스킬 | 실습 환경의 스킬이 ~6개라 오발동이 재현되지 않음 | 보스전 시작 멘트("주간 리그레션 리포트 만들어줘")가 라우팅의 입구임을 카드에서 설명 |
| ⑩ 자가 리뷰 루프 | ⑪과 "검증 프레임 전환"이 겹침 — 더 극적인 ⑪을 채택 | 이론 장 안내 |
| ⑬ 증거 기반 완료 | 단독 미션 대신 **보스전의 완료 조건**으로 통합 | Lv.13 성공 조건에 증거표 포함 |

## 5. 미션 카탈로그 — 사건 재현 → 할 일 → 채점

> 미션 카드 공통 형식은 2편 관례를 따른다: frontmatter(`id`/`level`/`track: adv`/`title`/`check: script`) + 사건 재현 + 목표 + 절차 힌트 + 성공 조건 + 검증 명령. 카드에는 15분 경과 시 열어보는 **접힌 힌트**를 1~2개 넣는다.

### M1 · Lv.8 `adv-script-offload` — "다시 고장난 log-digest" (사건 ②)

| 항목 | 내용 |
|---|---|
| 사건 재현 | 시즌 1에서 수리한 log-digest에게 이번엔 **50만 줄** 리그레션 로그(`tools/gen-big-log.py`로 생성, 시드 고정)를 요약시킨다 → 읽기 중단·집계 오답을 목격 |
| 할 일 | 제공된 `scripts/digest.py`를 스킬 폴더에 동봉하고, SKILL.md 절차를 "직접 읽지 않는다 → 스크립트 실행 → 출력만 근거로"로 개조. `## 금지`(원본 READ·직접 세기)와 `## 검증`(건수 합=TOTAL) 절 추가 |
| 성공 조건(채점) | `output/digest.md` 존재 · 끝줄 `DIGEST-VERSION: 1` · 4버킷(assertion/timeout/build/환경) 포함 · **유형별 건수가 정답과 일치**(시드 고정이라 기대값을 check.sh에 하드코딩) · SKILL.md에 digest.py 실행 절차와 금지 절 존재 |
| 배우는 것 | 크기와 비용의 분리 — 원본이 아무리 커도 컨텍스트 비용은 30줄 |

### M2 · Lv.9 `adv-artifact-contract` — "전달 사고" (사건 ⑥)

| 항목 | 내용 |
|---|---|
| 사건 재현 | 새 스킬 `incident-report`(skills-broken/ 제공 — 입력의 위치·형식 미정 상태)에 리포트를 시키면, digest 결과를 사람이 복붙해 줘야 하고 구버전 파일을 집어 쓴다 |
| 할 일 | **새 스킬을 만들지 않는다** — 두 스킬에 약속을 한 절씩: log-digest에 쓰는 쪽 약속(경로 `output/digest.md` · 3섹션 형식 `## 요약 / ## 오류 Top 10 / ## 이상 징후` · 끝줄 버전), incident-report에 읽는 쪽 약속(digest.md만 근거 · 버전 없으면 구버전 간주 · 없으면 안내 후 정지) |
| 성공 조건(채점) | digest.md 3섹션+버전 · `output/report.md`에 근거 표시줄(`SOURCE: output/digest.md (DIGEST-VERSION: 1)`) · 리포트의 건수가 digest 수치와 일치(전달 무결성) · **digest.md를 지운 상태에서 리포트를 시키면 멈추는지** 자가 확인(2편 Lv.4 방식의 y/n 문답) |
| 배우는 것 | 약속이 책임지는 건 전달까지 — 내용 검사는 M3의 게이트 몫(⑥/⑧ 구분을 카드에 명시) |

### M3 · Lv.10 `adv-pipeline` — "새벽 2시 훈련" (사건 ⑦ + ⑧)

| 항목 | 내용 |
|---|---|
| 사건 재현 | 부품 4개(log-digest · root-cause* · incident-report · report-check* — *는 완성본 제공)가 있지만 순서를 아는 스킬이 없다 — "장애 대응 시작해줘" 한 마디로는 아무 일도 안 일어난다 |
| 할 일 | 지휘 스킬 `incident-flow`를 **템플릿 빈칸 채우기**로 완성 — 단계표(1 수집→2 분석→3 초안→4 검증, 단계별 산출물 경로), 진행 규칙(flow-log 한 줄 보고 · 산출물 있으면 SKIP=중간 재개), `## 금지`. **게이트는 한 곳만**: 3단계 진입 전 제공된 `gate.py` 실행. **반려 이벤트 내장**: 제공된 root-cause가 재현 절차를 TBD로 남겨 1차 실행은 반드시 GATE FAIL → flow가 analysis.md를 `analysis.rejected.md`로 이동(반려)하고 멈춤 → 카드의 교체 텍스트로 root-cause 보완 → 재실행에서 SKIP 1/4(중간 재개 체감)과 GATE PASS |
| 성공 조건(채점) | "장애 대응 시작해줘" 한 마디 후 산출물 4종 + `flow-log.md` — flow-log에서 `STEP 1/4`·`GATE: FAIL`·`SKIP 1/4`·`GATE: PASS`·`STEP 4/4`를 전부 grep(반려→재개→완주가 객관 채점됨, 자가 확인 문답 불필요) · analysis.md에 TBD 없음 · incident-flow에 금지 절 존재 |
| 배우는 것 | 프로세스도 스킬이다 + 게이트는 연결마다가 아니라 부실이 비싸지는 길목 한 곳 |

### M4 · Lv.11 `adv-validate-loop` — "검산기 은퇴식" (사건 ⑫)

| 항목 | 내용 |
|---|---|
| 사건 재현 | 새 주차 데이터 `data/test_results_week34.csv`(함정 포함 — 중복 행·SKIP 상태)로 test-report를 돌리면 합계가 어긋난 리포트가 나온다 — 사람이 검산기가 되는 상황 재현 |
| 할 일 | 제공된 `validate-skeleton.py`의 채점 규칙 3곳(필수 섹션 · PASS+FAIL=전체 · 금지 문구)을 채워 `test-report/scripts/validate.py`로 동봉. SKILL.md 절차에 "작성 → validate 실행 → FAIL이면 수정 후 재실행, **PASS까지 반복(최대 5회)** → PASS 원문을 리포트 끝에 첨부" 루프 명시 |
| 성공 조건(채점) | `output/test-report-v3.md`에 정답 합계 · `VALIDATE: PASS` 원문 첨부 · validate.py가 스킬 폴더에 존재하고 세 규칙이 동작(check.sh가 고의 오류 파일로 validate.py를 역채점) · SKILL.md에 루프 상한 명시 |
| 배우는 것 | 판정은 코드가, 수정은 모델이 — 그리고 지금까지 돌린 check.sh가 바로 이 구조 |

### M5 · Lv.12 `adv-refute` — "그럴듯한 오답" (사건 ⑪) — 수료 미션

| 항목 | 내용 |
|---|---|

## 7. 실습 리포 확장 구성안 (`seminar_ai_skill_quest`에 추가)

**출제 실물은 본 리포 [`quest-adv/`](../quest-adv/)에 스테이징되어 있다** — 폴더 구조가 실습 리포 최상위와 1:1이라 그대로 복사가 곧 병합이다(적용 명령은 `quest-adv/README.md`). 채점기는 기존 `check.sh`를 수정하지 않고 **별도 파일(`check-adv.sh/.ps1/.bat`)**로 두어 병합 충돌을 없앴다 (SALT·코드 산식은 동일 — 보드 검증 로직 무변경).

```text
quest-adv/                                ← 스테이징 (실습 리포 루트에 그대로 복사)
├─ missions/lv8~lv13, ex/                 ← 미션 카드 7장 (track: adv, 접힌 힌트 동봉)
├─ tools/gen-big-log.py                   ← M1용 50만 줄 생성기 — 오류 수 고정(1842·317·96·41·02:14), --lines 축소판도 동일
├─ scripts-given/                         ← digest.py·gate.py(완성) · validate-skeleton.py(빈칸 3곳) · fixtures/bad-report.md(역채점용)
├─ data/                                  ← test_results_week34.csv(중복·SKIP 함정) · incident/ 5일 로그(진짜 원인: 8/10 cert 만료) · analysis-draft.md
├─ skills-broken/incident-report/         ← M2 시작점 (입력 위치·형식 미정)
├─ skills-given/                          ← root-cause(TBD 함정 내장) · report-check · snapshot-s1/(시즌 1 세이브 파일)
├─ skills-templates/                      ← incident-flow · refute-check · regression-weekly (빈칸 템플릿)
├─ check-adv.sh / .ps1 / .bat             ← 시즌 2 채점기 (GROW-L8~13 발급)
└─ answer-key/                            ← 진행자용 — 빈칸 정답·채점 기대값·리허설 워크스루·완성본
board/skill-quest-board.html              ← Lv.8~13 확장 (별도 작업 — 전까지는 "코드 수첩" 운영 가능)
```
